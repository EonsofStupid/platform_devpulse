# Button Primitive - Accessibility Contract

## ARIA Behavior

| Attribute | Value | Notes |
|-----------|-------|-------|
| `role` | `button` | Implicit via native `<button>` element |
| `aria-disabled` | `true` when disabled | Automatically set by Bits UI |
| `tabindex` | `0` (focusable) | Native button behavior |

## Keyboard Interaction

| Key | Action |
|-----|--------|
| `Enter` | Activates the button |
| `Space` | Activates the button |
| `Tab` | Moves focus to next focusable element |
| `Shift+Tab` | Moves focus to previous focusable element |

## Focus Management

- Button receives focus on `Tab`
- Focus ring visible via `:focus-visible`
- Focus maintained until explicitly moved

## Data Attributes

| Attribute | Values | Purpose |
|-----------|--------|---------|
| `data-kind` | `"button"` | Identifies primitive type for CSS targeting |
| `data-slot` | `"root"` | Identifies slot for CSS targeting |
| `data-state` | `"pressed"` \| `"disabled"` \| `undefined` | Current interaction state |
| `data-id` | user-defined | Stable ID for tooling/testing |

## State Transitions

```
[idle] --press--> [pressed] --release--> [idle]
[idle] --disable--> [disabled]
[disabled] --enable--> [idle]
```

## Screen Reader Behavior

- Announces button label (from content or `aria-label`)
- Announces disabled state
- Announces button role

## Touch Target

- Minimum 44x44px recommended for touch devices
- Achieved via padding in recipes, not primitive

## Usage Example

```svelte
<Button disabled={isLoading} onclick={handleClick}>
  Submit
</Button>
```

## Testing Requirements

1. **Keyboard activation**: Verify Enter and Space trigger onclick
2. **Focus visible**: Verify focus ring appears on keyboard focus
3. **Role/label**: Verify `role="button"` and accessible name present
4. **Disabled state**: Verify button not activatable when disabled
