# Sheet Primitive - Accessibility Contract

> Sheet is a Dialog variant that slides in from a side (left, right, top, bottom).
> Same ARIA behavior and focus management as Dialog.

## ARIA Behavior

| Attribute | Element | Value | Notes |
|-----------|---------|-------|-------|
| `role` | Content | `dialog` | Implicit via Bits UI |
| `aria-modal` | Content | `true` | Implicit via Bits UI |
| `aria-labelledby` | Content | Title ID | Auto-linked by Bits UI |
| `aria-describedby` | Content | Description ID | Auto-linked by Bits UI |
| `aria-haspopup` | Trigger | `dialog` | Implicit via Bits UI |
| `aria-expanded` | Trigger | `true/false` | Implicit via Bits UI |

## Keyboard Interaction

| Key | Action |
|-----|--------|
| `Enter` | Opens sheet (on Trigger) |
| `Space` | Opens sheet (on Trigger) |
| `Escape` | Closes sheet |
| `Tab` | Cycles through focusable elements (trapped) |
| `Shift+Tab` | Cycles backwards through focusable elements |

## Focus Management

1. **When sheet opens:**
   - Focus moves to first focusable element inside Content
   - Focus is trapped within Content (Tab cycles)
   - Background scroll is locked
   - Background content is inert (not focusable)

2. **When sheet closes:**
   - Focus returns to Trigger element
   - Scroll lock released
   - Background content restored

## Data Attributes

| Attribute | Values | Purpose |
|-----------|--------|---------|
| `data-kind` | `"sheet"` | Identifies primitive type for CSS |
| `data-slot` | `"root"` `"trigger"` `"portal"` `"overlay"` `"content"` `"title"` `"description"` `"close"` | Identifies slot for CSS |
| `data-state` | `"open"` `"closed"` | Current state for CSS animations |
| `data-side` | `"left"` `"right"` `"top"` `"bottom"` | Side the sheet slides from (Content only) |
| `data-id` | user-defined | Stable ID for tooling/testing |

## CSS Targeting

```css
/* Target sheet overlay when open */
[data-kind="sheet"][data-slot="overlay"][data-state="open"] {
  opacity: 1;
}

/* Target sheet content by side */
[data-kind="sheet"][data-slot="content"][data-side="right"] {
  transform: translateX(0);
}

[data-kind="sheet"][data-slot="content"][data-side="left"] {
  transform: translateX(0);
}

[data-kind="sheet"][data-slot="content"][data-side="top"] {
  transform: translateY(0);
}

[data-kind="sheet"][data-slot="content"][data-side="bottom"] {
  transform: translateY(0);
}
```

## Screen Reader Behavior

- Announces sheet title when opened
- Announces sheet description if present
- Background content hidden from screen readers via `aria-hidden`

## Sheet-Specific Considerations

### Side Prop

The `side` prop on Content determines which edge the sheet slides from:

- `"left"` - Slides in from left edge
- `"right"` - Slides in from right edge (default)
- `"top"` - Slides in from top edge
- `"bottom"` - Slides in from bottom edge

### Use Cases by Side

| Side | Typical Use Case |
|------|------------------|
| `left` | Navigation menus, sidebars |
| `right` | Settings panels, detail views, forms |
| `top` | Notifications, banners |
| `bottom` | Mobile actions, confirmations |

## Testing Requirements

1. **Open/Close**: Verify trigger opens, escape/close button closes
2. **Focus trap**: Verify Tab cycles only within sheet
3. **Focus return**: Verify focus returns to trigger on close
4. **ARIA**: Verify `role=dialog`, `aria-modal=true`, `aria-labelledby`
5. **Data attributes**: Verify all slots have correct attributes
6. **Keyboard**: Verify Enter/Space on trigger, Escape to close
7. **Side**: Verify `data-side` attribute on Content for all 4 sides
