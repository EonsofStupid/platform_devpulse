## 7. Risks / pre-mortem

- **Risk 1:** ServiceStatus value drift. If the engine emits a
  `Failed` variant the frontend doesn't know about, the UI shows
  blank. — **mitigation:** exhaustive match in
  `surrealdbSidecar.state.svelte.ts`; emit `console.warn` on unknown
  variants so it surfaces in dev.
- **Risk 2:** Polling thrash. Naive polling at 500ms across many
  services costs CPU. — **mitigation:** match Ollama's 2s interval;
  add a TODO to switch to event-push later.
- **Risk 3:** Auto-generated `service-manifest.ts` drifts from manual
  edits. — **mitigation:** never edit it by hand; always run `cargo
  xtask regen-bindings` after backend changes.
- **Steel-man (alternative not chosen — Tauri events instead of
  polling):** pushes status from backend, eliminates poll cost, more
  responsive UI. Skipped for this PR because Ollama uses polling and
  consistency matters more than the optimization right now.
