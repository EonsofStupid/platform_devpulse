## Critical Findings (4)

1. **No hypermodular service folders.** All four services are flat files in shared `systems/devpulse-engine/src/platform/services/` directory. The spec calls for "each properly in platform industry nested folder. Each in their own boundary/folder. Each hypermodular." No `services/libsql/`, no `services/duckdb/`, no `services/surreal/`, no `services/devforge/`. The `services/` `mod.rs` explicitly enumerates each flat file.
2. **Zero log export anywhere.** None of the 4 devtools (`routes/(devtools)/devtools/{libsql,duckdb,surreal,devforge}/+page.svelte`) have a log export / download mechanism.
3. **`std::sync::Mutex` held across `.await` in DevForge shutdown.** `services/devforge.rs` lines 210-218:
   ```rust
   async fn shutdown(&self) -> Result<()> {
       let mut guard = self.child.lock().map_err(|e| anyhow!("Lock poisoned: {e}"))?;
       if let Some(mut child) = guard.take() {
           let _ = child.start_kill();
           let _ = child.wait().await;   // .await with std::sync::Mutex guard held
       }
       Ok(())
   }
   ```
4. **DevForge `update_channel_url` is dead.** `DevForgeServiceEntry.update_channel_url` field (config.rs:1123) is parsed from TOML and stored in the struct but **never read by any runtime code**. The spec calls for "dedicated built in Rust for live updates" — that code does not exist. The only update path is `xtask fetch-devforge` at build time.

## Major Findings (5)

5. **No restart controls for any service.** None of `commands/sys/{relational,analytics,graph}.rs` or `commands/devforge/mod.rs` expose `restart`, `stop`, or `start`. Health + list + query only.
6. **No dedicated system accounts for LibSQL / DuckDB / DevForge.** Only SurrealDB has credentials (hardcoded plaintext defaults in `config.rs:565/580/595`: `devpulse_engine / dp_sys_2026!` etc). `ServiceEntry` for LibSQL/DuckDB has no `system_user`/`system_password` fields.
7. **DevForge has no live update runtime.** `update_channel_url` is a dead config field (see #4). No `reqwest`, no `self_update`, no release polling, no in-app download in runtime code.
8. **Grammar service state duplicated without documented SSOT.** Mirrored in LibSQL (`grammar_service` table) and SurrealDB system graph (`grammar_service` table). Declared as intentional mirror at `graph.rs:186`, but the source of truth between the two is not documented.
9. **`stop_reh_server` is a documented no-op.** `commands/devforge/mod.rs:57-59`:
   ```rust
   pub async fn stop_reh_server(_state: State<'_, PlatformState>) -> Result<(), String> {
       Ok(())
   }
   ```
   Frontend compat stub. Actual stop happens only at process shutdown.

## Minor Findings (2)

10. Error messages in devtools are raw Rust error strings surfaced verbatim. Not layman-phrased.
11. No schema version / migration path for any of the three databases. One-shot DDL at open only.

## Cross-Cutting

- **Single boot entry point**: YES — `Platform::boot()` in `systems/devpulse-engine/src/platform/mod.rs:219`. No parallel bootstrap paths.
- **SSOT violations**: grammar_service mirrored across LibSQL + SurrealDB without documented primary.
- **Hard gates in frontend**: `+layout.svelte` does NOT hard-block children render on `platformState.isReady`. Only the `BootOverlay` component is imported; its current behavior was already changed in recent commits.
- **Competing lifecycles**: DevForge has no respawn / watchdog. If the Node REH child dies mid-session, `state()` returns `Failed` but nothing restarts it.
- **Orphaned files / dead fields**: `DevForgeServiceEntry.update_channel_url` is dead.

## What Is Missing Against Spec — Shortlist For Rebuild

1. Hypermodular per-service folders under `services/` and `boot/` and `commands/sys/`.
2. Start / Stop / Restart commands for each of the 4 services + corresponding devtool controls.
3. Log export + download from each devtool.
4. Dedicated system account / credential layer for LibSQL + DuckDB + DevForge (SurrealDB has plaintext today — needs secrets management regardless).
5. DevForge runtime live-update path in Rust (consume `update_channel_url`).
6. Fix DevForge `shutdown()` — switch `std::Mutex` to `tokio::sync::Mutex` or drop guard before `.await`.
7. Layman-phrased error surfaces in all 4 devtools.
8. Documented SSOT for grammar_service (LibSQL or SurrealDB — pick one).
9. Schema migration / version path for the three databases.
10. DevForge respawn / watchdog logic OR documented intentional non-restart behavior.
