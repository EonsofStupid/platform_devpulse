## 1. TOKEN PIPELINE GAPS

### 1.1 Primitives Leaking Into Tailwind Autocomplete
- **Severity**: CRITICAL
- **Location**: `theme/color.css`
- **Problem**: 55 raw primitive color scales (red, orange, amber, yellow, chartreuse, lime, etc.) registered in `@theme`. Tailwind generates `bg-red-500`, `text-amber-400` etc. Developers use raw palette instead of semantic tokens.
- **Fix**: Filter `@theme` output to ONLY semantic tokens. Raw palette stays in `:root` CSS for StyleMacro but NOT in Tailwind autocomplete.

### 1.2 Typography Composites Not Composed for Tailwind
- **Severity**: HIGH
- **Location**: `theme/typography.css`, `sd.config.mjs`
- **Problem**: DTCG textStyle composites (display-lg, heading-sm, body, caption, code, stat) expand into individual properties (`--text-style-display-lg-font-size`, etc.). Tailwind needs composed format: `text-display-lg` → all 5 properties at once.
- **Fix**: Custom SD5 format that reassembles textStyle composites into Tailwind's fontSize tuple format.

### 1.3 No Fluid Responsive Tokens
- **Severity**: CRITICAL
- **Location**: ALL token output
- **Problem**: Every dimension token is a static value. No `clamp()`. No fluid scaling. UI breaks at different viewport sizes.
- **Fix**: ALL dimension tokens (spacing, font-size, container, padding, radius) must use `clamp(min, preferred, max)` for true fluid scaling. Author responsive formulas in DTCG source. SD5 outputs `clamp()` values.

### 1.4 $type-Based Routing Not Used
- **Severity**: MODERATE
- **Location**: `sd.config.mjs`
- **Problem**: Token routing uses path-based filters (`pathFilter('color')`). If token path doesn't match filter name, it falls to wrong tier silently. DTCG `$type` field is more reliable.
- **Fix**: Hybrid routing — check `$type` first, fall back to path.

### 1.5 Style Preset Missing Properties Resolve to "inherit"
- **Severity**: MODERATE
- **Location**: `style-presets.json`, `components.generated.css`
- **Problem**: Enrichment script set font-family, font-size, font-weight, line-height to `"inherit"` as string type. SD5 outputs them but CSS value `inherit` from a CSS var doesn't cascade the same as an unset property. Some components show wrong typography.
- **Fix**: Either set proper values per preset or use `unset` / remove the property declaration entirely.

### 1.6 SVG Presets Use `outputReferences: true` — Inconsistent With HTML
- **Severity**: LOW
- **Location**: `sd.config.mjs` css-svg-presets platform
- **Problem**: SVG presets pass `var()` references through (for accent injection). HTML presets use `outputReferences: false` (fully resolved). Two different strategies in one pipeline.
- **Fix**: Document this as intentional (SVG accent vars MUST pass through). Not a bug but needs explicit documentation.

### 1.7 Aliases.css Is a Bandaid Layer
- **Severity**: HIGH
- **Location**: `generated/aliases.css`
- **Problem**: 25 hand-authored vars that bridge naming gaps between SD5 output and consumer expectations. These should ALL be in DTCG source and generated by SD5. Hand-authored CSS bypasses the pipeline.
- **Tokens to migrate to DTCG**:
  - `--border-soft`, `--border-emphasis` → author in `border.json`
  - `--overlay-bg`, `--overlay-bg-heavy` → author in `overlay.json`
  - `--accent-{hue}-main/glow/fill` (18 vars) → author in new `accent.json`
  - `--svg-track-stroke`, `--svg-track-tick-stroke` → author in `svg-presets.json`
  - `--status-dot-glow-radius` → author in component preset or delete

## 2. FOLDER STRUCTURE GAPS

### 2.1 Behaviors Folder Has Mixed Content
- **Severity**: CRITICAL
- **Location**: `design/behaviors/`
- **Problem**: ALL 74 behavior folders contain BOTH `.svelte` structural primitives AND `use-*.svelte.ts` behavior hooks mixed together. The `.svelte` files are pure structural shells (no behavior, no ARIA). They belong in `primitives/`, not `behaviors/`.
- **Fix**: Split every folder — `.svelte` + `.props.ts` to `primitives/`, hooks + `.a11y.ts` + `.anatomy.ts` + `.types.ts` stay in `behaviors/`.

### 2.2 Primitives Folder Is Empty
- **Severity**: CRITICAL
- **Location**: `design/primitives/`
- **Problem**: Folder exists but is empty. The structural primitives are trapped in `behaviors/` (see 2.1).
- **Fix**: Populate after split from behaviors.

### 2.3 Blocks Still Contain SVG Components
- **Severity**: MODERATE (partially fixed)
- **Location**: `blocks/widgets/RadialGauge.svelte`, `blocks/widgets/SparkLine.svelte`
- **Problem**: Old SVG widget files still exist alongside new `components/radial-gauge/` and `components/spark-line/`. Dead code.
- **Fix**: Delete old files from `blocks/widgets/`.

### 2.4 Actions + API Folders Not Merged Into Attachments
- **Severity**: MODERATE
- **Location**: `design/actions/`, `design/api/`
- **Problem**: Old Svelte action and API adapter folders exist separately. Svelte 5 uses attachments. These should merge into `design/attachments/`.
- **Fix**: Create `attachments/` folder, move contents, update imports.

### 2.5 Dead Folders Still Exist
- **Severity**: LOW
- **Location**: `design/variants/`, `design/scrollbars/`, `design/focus/`, `design/typography/`, `design/presets/`, `design/provider/`, `design/schema/`
- **Problem**: Multiple folders that may be dead or duplicated. Need audit to confirm if any have live consumers.
- **Fix**: Audit each, delete dead ones.

### 2.6 Domain Component in Central Library
- **Severity**: MODERATE
- **Location**: `blocks/governance/GovernanceControls.svelte`
- **Problem**: GovernanceControls is a domain-specific composition (CAG/Maestro UI). It belongs in `domains/`, not in the central library.
- **Fix**: Move to `domains/app/maestro/` or extract generic "parameter panel" primitive.

## 3. COMPONENT GAPS

### 3.1 StyleMacro Intent Resolver Missing Visual Pass-Through
- **Severity**: FIXED (2026-03-26)
- **Location**: `styles/StyleMacro.svelte`
- **Problem**: Visual preset names (glass, flat, matte, stark) weren't in INTENT_MAP. Passing `intent="glass"` resolved to `"default"`.
- **Status**: Fixed — visual names now pass through.

### 3.2 Badge Uses `variant` Not `intent` in Routes
- **Severity**: HIGH
- **Location**: 5 route files, 16 Badge instances
- **Files**: devforge/+page, maestro/+page, overmind/+page, wiredfront/+page, StatusBar.svelte
- **Problem**: Routes pass `variant="neutral"` / `variant="positive"` to Badge. Badge has both `variant` and `intent` props. `variant` is destructured but only used for data attribute, not for StyleMacro.
- **Fix**: Either route Badge `variant` through to StyleMacro, or change routes to use `intent`.

### 3.3 StatusDot Refs Nonexistent Vars
- **Severity**: FIXED (2026-03-26)
- **Location**: `components/status-dot/StatusDot.svelte`
- **Problem**: Referenced `--status-dot-root-color-{status}` and `--status-dot-root-glow-radius` — never existed in DTCG.
- **Status**: Fixed — now uses signal/text tokens directly.

### 3.4 Stat Refs Nonexistent Vars
- **Severity**: PARTIALLY FIXED (2026-03-26)
- **Location**: `components/stat/Stat.svelte`
- **Problem**: Referenced `--stat-root-*` vars that never existed. Rewritten to use accent/text tokens.
- **Status**: Rewritten but not yet wired into dashboard.

### 3.5 Card Has Both `variant` and `intent` Props
- **Severity**: MODERATE
- **Location**: `components/card/card.types.ts`
- **Problem**: `CardVariant` and `CardIntent` are two different type unions. `variant` is destructured but not used by StyleMacro. Confusing API — two props for the same purpose.
- **Fix**: Deprecate `variant`, standardize on `intent` only.

### 3.6 AlertDialog, Collapsible, Dialog, NavigationMenu Hardcode Style IDs
- **Severity**: MODERATE
- **Location**: 4 component files
- **Problem**: These pass `style="alert-dialog-default"` etc. to StyleMacro instead of using `intent` prop with resolver. Bypasses intent system.
- **Fix**: Change to `intent="default"` and remove `style` override.

### 3.7 Alert, Callout, ChatBubble Use `intent={variant}` Naming Mismatch
- **Severity**: LOW
- **Location**: 3 component files
- **Problem**: These have a `variant` prop but pass it to StyleMacro as `intent={variant}`. Semantically confusing — same value, different name at different layers.
- **Fix**: Rename their prop from `variant` to `intent` for consistency.

### 3.8 Components Don't Use Primitives
- **Severity**: CRITICAL
- **Location**: ALL components
- **Problem**: No component is built on a primitive. They all render raw HTML elements directly. The primitives folder is empty (see 2.2). The entire library lacks the foundational visual atom layer.
- **Fix**: Extract visual primitives from behaviors, build each component on its primitive.

### 3.9 Chat Components Not Rendering
- **Severity**: HIGH
- **Location**: `routes/(chat)/chat/+page.svelte`
- **Problem**: Chat page uses Card, ThreadList, ChatPanel but none render visible UI. ThreadList hardcodes var() refs instead of using components. ChatPanel delegates to Card but Card's glass treatment doesn't paint on chat elements.
- **Fix**: Wire chat components through StyleMacro properly. Build ThreadList on proper primitives.

### 3.10 Store Health / Recent Projects Use Raw Markup
- **Severity**: HIGH
- **Location**: `routes/(app)/devpulse/+page.svelte` lines 195-275
- **Problem**: Health rows and project cards use `cn(box({}))` — raw divs with utility functions that produce no StyleMacro-backed visual output. No components for these patterns.
- **Fix**: Build proper components (or compose from existing) and wire through StyleMacro.

## 4. SVG ENGINE GAPS

### 4.1 SVG Engine Built But Widgets Not Fully Migrated
- **Severity**: MODERATE
- **Location**: `svg/`, `components/radial-gauge/`, `components/spark-line/`
- **Problem**: SVG engine infrastructure (resolver, mappings, glue CSS, presets) is built. RadialGauge and SparkLine migrated. But old copies still in `blocks/widgets/`. Dashboard wired to new imports but not all visual effects confirmed working.
- **Fix**: Delete old files, verify visual rendering matches DASHBOARD-REFERENCE-01.

### 4.2 SVG `stroke-linecap` Can't Use CSS Vars in Svelte
- **Severity**: LOW
- **Location**: RadialGauge, SparkLine
- **Problem**: SVG `stroke-linecap` attribute is typed as enum in Svelte — can't pass `var(--cl-svg-stroke-linecap)`. Hardcoded to `"round"` as workaround.

### 4.3 No SVG Presets for Future Widget Types
- **Severity**: LOW (future)
- **Location**: `tokens/src/svg-presets.json`
- **Problem**: Only radial-gauge and spark-line presets exist. Future widgets (bar-chart, line-chart, node-graph) need presets authored when built.
- **Fix**: Author presets per widget kind as each is built.

## 11. SURREALDB / MCP GAPS

### 11.1 Two SurrealDB Instances — Architecture Mismatch
- **Severity**: HIGH
- **Location**: `scripts/surrealdb/ARCHITECTURE.md` vs actual running instance
- **Problem**: ARCHITECTURE.md describes TWO separate instances: embedded (compiled into binary, port N/A) and standalone (port 8000, for AI agents). The actual running instance is the EMBEDDED one on port 8822 with a custom axum HTTP wrapper. The standalone instance on port 8000 is NOT running. The architecture doc describes a dual-instance model that doesn't match reality.
- **Fix**: Decide: is the standalone instance needed, or does the embedded HTTP API (8822) serve both purposes? Update ARCHITECTURE.md to match actual architecture.

### 11.2 Standalone SurrealDB Not Running
- **Severity**: HIGH
- **Location**: Port 8000
- **Problem**: `curl -s http://127.0.0.1:8000/health` returns nothing. The standalone instance described in ARCHITECTURE.md is not started. AI agent memory tables (sessions, chat, files_touched, blockers) are not available.
- **Fix**: Either start standalone instance or confirm embedded HTTP API replaces it.

### 11.3 .mcp.json Points to Docker + Wrong Port
- **Severity**: HIGH
- **Location**: `.mcp.json`
- **Problem**: MCP config uses Docker (`ghcr.io/surrealdb/surrealmcp:latest`) connecting to `ws://host.docker.internal:8000/rpc`. Docker is banned per ADR-001. Port 8000 isn't running. WebSocket `/rpc` isn't exposed on embedded instance (8822).
- **Fix**: Replace Docker MCP with direct curl-based access to embedded HTTP API on 8822, or build the MCP bridge (planned sprint).

### 11.4 Schema Mismatch Between Architecture Doc and Actual DB
- **Severity**: HIGH
- **Location**: ARCHITECTURE.md schemas vs embedded instance tables
- **Problem**:
  - Doc says `learnings` table with fields: category, trigger, wrong_action, correct_action, severity
  - Actual DB has `shared_learnings` table with fields: pattern, confidence, reinforcement_count, source_projects
  - Doc says namespace `projects/devpulse` with tables: architecture, patterns, context, decisions, tasks
  - Actual DB has no `projects` namespace — has `system/engine`, `user/profile`, `global/knowledge`
- **Fix**: Reconcile schemas. The embedded instance schema (platform.default.toml driven) is the source of truth. ARCHITECTURE.md is stale.

### 11.5 Hooks Don't Exist
- **Severity**: MODERATE
- **Location**: `~/.claude/hooks/`
- **Problem**: ARCHITECTURE.md describes hooks (on-session-start.js, on-file-write.js) that restore SurrealDB context. The hooks directory DOES NOT EXIST. Zero hooks are installed.
- **Fix**: Either build hooks or accept that preflight skill replaces them.

### 11.6 Seed Scripts May Not Match Current Schema
- **Severity**: MODERATE
- **Location**: `scripts/surrealdb/seed-global.surql`, `seed-devpulse.surql`
- **Problem**: Seed scripts exist but may target the standalone instance schema, not the embedded instance schema. If run against the embedded instance, they'll fail on schema mismatches.
- **Fix**: Audit seed scripts against actual embedded DB schema. Rewrite if needed.
