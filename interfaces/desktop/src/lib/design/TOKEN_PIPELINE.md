# ColdLight Token Pipeline

> How tokens flow from DTCG JSON source to generated outputs via Style Dictionary 5.
> Brought to current truth 2026-07-11 (FUBAR audit slice 1 — the previous
> revision described a `sd.config.ts`/`css/`-dir pipeline that no longer exists).

---

## Overview

```
tokens/src/** (DTCG 2025.10, ~129 files: primitives/ + semantic/ + presets/ + collected)
  → collect-element-seed-defs.mjs   (component @defaults doc-headers → style-defaults.json)
  → derive-kind-families.mjs        (KIND_FAMILIES + PRESET_FAMILIES → renderforge/generated/kind-families.ts)
  → SD5 buildAllPlatforms (sd.config.mjs)
      → coldlight/css            → styles/{primitives,semantic,components}/*.css   (@layer tokens.*)
      → coldlight/tailwind-theme → theme/*.css                                     (@theme + @theme inline)
      → coldlight/types          → types/*.d.ts
      → coldlight/manifest       → generated/token-manifest.json
  → build.mjs DERIVES barrels from emitted files (styles/index.css, theme/index.css,
      types/index.d.ts) + prunes F9-skipped empty theme files — never hand-listed
```

**Command**: `pnpm ds:tokens:build`
**Regression harness**: `pnpm audit:cssvars` (custom-property chain), `pnpm audit:deps`, `pnpm audit:unused`

## Layering contract (LOCKED — audit finding F2)

`styles/index.css` declares `@layer tokens.primitives, tokens.semantic, tokens.components;`
and **every SD5-emitted CSS file, including `components.generated.css`, is wrapped
in its `@layer tokens.{tier}`** by the `coldlight/css` format. Never emit token CSS
unlayered: unlayered declarations outrank every layer and hand the cascade to
load order — this was the mechanism behind the monochrome-teal failure.

Tier routing (`sd.config.mjs` `tiers`): `path[0]` ∈ primitives list → `tokens.primitives`;
∈ semantic list → `tokens.semantic`; everything else (`style.*`, `preset.*`) →
`tokens.components`.

## @theme reference contract (audit finding F5 + F9 namespace guard)

`coldlight/tailwind-theme` emits **two blocks per domain**:

- `@theme { ... }` — raw-valued tokens, as literals.
- `@theme inline { ... }` — whole-value `{ref}` tokens, as `var(--target)` pointers.
  `inline` is required by Tailwind for var()-valued theme variables
  (tailwindcss.com/docs/theme); utilities resolve at the use site.

Never flatten a reference-valued token into a literal in `@theme` — that freezes
the binding and silently breaks role rebinds.

**Namespace guard (F9, 2026-07-17).** `theme/`'s ONLY job is to register Tailwind
utilities. A token is emitted to `theme/` **only if `toTw4VarName(token)` lands on a
real Tailwind v4 theme namespace** (`--color-*`, `--font-*`, `--text-*`,
`--font-weight-*`, `--tracking-*`, `--leading-*`, `--tab-size-*`, `--breakpoint-*`,
`--container-*`, `--spacing-*`, `--radius-*`, `--shadow-*`, `--inset-shadow-*`,
`--drop-shadow-*`, `--blur-*`, `--perspective-*`, `--zoom-*`, `--aspect-*`,
`--ease-*`, `--animate-*`). Anything else (`--gradient-*`, `--transition-*`,
`--surface-*`, `--elevation-*`, `--accent-*`, `--border-*`, `--backdrop-*`,
`--{role}-*`, `--signal-*`, `--interaction-*`, `--overlay-*`, `--scrollbar-*`)
generates **no utility** and is skipped entirely — it lives ONLY in `styles/`
(layered). Emitting it to `theme/` would put an **unlayered** copy on top of the
layered `styles/` value, and unlayered always outranks `@layer` — the exact
mechanism behind the 644 cascade collisions (`audit:cssvars` CONTESTED). The
namespace-valid domains that *do* collide (`--color-*`, `--radius-*`, `--shadow-*`,
`--blur-*`, `--spacing-*`, font/text sizes) are BENIGN: same value from the same
source, and Tailwind v4 requires the `@theme` copy to mint the utility.

## Role vocabulary (CANONICAL — audit F7 resolution)

Components consume **`--accent-{role}-{main,glow,fill}`**
(`primary` / `secondary` / `danger` / `success` / `warning` / `muted`) —
emitted from `semantic/accent/accent.tokens.json` as pure aliases of the
**role binding SSOT** `semantic/role/role.tokens.json` (`--{role}-*`,
primary=blue per locked product requirement #6, secondary=ember,
danger/success/warning=signal seeds).

- Rebind a role → edit `role.tokens.json` only.
- Components MUST NOT reach for palette names (`--accent-teal-*`) or raw ramps
  (`--color-*`).
- The legacy `--accent-main` quartet and `--primary-*` names survive as aliases
  during migration; new code uses `--accent-{role}-*`.
- The hand-authored role shim previously in `src/app.css` is retired; only the
  backdrop mirrors and the button-primary preset retarget remain there until
  Phase 2 re-sources the preset tier.

## Authoring Rules

- DTCG 2025.10 format: `$type` on group, `$value` on leaf, `$description` everywhere.
- Colors: DTCG color objects `{ colorSpace: "oklch", components, alpha?, hex }`.
- References: `{group.path.leaf}` — absolute from the token root.
- glow/fill convention: same hue as the paired `main`, alpha 0.35 / 0.08.
- Dimensions: DTCG dimension objects; transforms emit rem (and clamp() for fluid).
- Extensions: `$extensions["com.coldlight"]` for VPB scale/control metadata.
- The shared preset layer (`presets/*.tokens.json`) is hand-maintained; its color
  axes are being converted from literals to `{refs}` in Phase 2 of the FUBAR plan.

## Adding a New Token

1. Add to the right file under `tokens/src/{primitives|semantic|presets}/`.
2. If it introduces a new `path[0]` root, register it in `tiers` AND in a
   platform file entry in `sd.config.mjs` — **SD5 silently drops token groups
   with no registered output file** (audit F8; see the 2026-07-07 reconciliation
   notes in sd.config.mjs).
3. Run `pnpm ds:tokens:build`; commit source + generated output together.
4. Verify with `pnpm audit:cssvars` — the new var must not land in UNDEFINED
   or CONTESTED.

## Core Truths

| Truth | Enforcement |
|-------|-------------|
| DTCG JSON is SSOT | Never edit generated styles/theme/types files |
| All token CSS is layered | `coldlight/css` wraps every file in `@layer tokens.{tier}` |
| References stay live | `outputReferences: true` everywhere; `@theme inline` for refs |
| Roles over palette | Components bind `--accent-{role}-*`; rebind in role.tokens.json |
| VPB reads manifest | `$extensions["com.coldlight"]` metadata drives editor controls |
